\section{Appendix E: Naming Conventions}
\label{app:naming}
% ===================================================================

This appendix documents the naming conventions used throughout the FRFP Lean
formalization. Consistent naming enables grep-based navigation and prevents
name collisions across 21 modules.

\subsection*{General Principles}

\begin{enumerate}
  \item \textbf{Lean 4 style}: Follow Lean 4 community naming (snake\_case for
        definitions, theorems, and axioms; CamelCase for types and structures).
  \item \textbf{Layer prefix}: Module-specific constants are prefixed with
        a short module abbreviation (e.g., \texttt{float\_}, \texttt{sem\_},
        \texttt{gov\_}).
  \item \textbf{Source annotation}: Every axiom has a comment on the preceding
        line: \texttt{-- Reference: [Author Year], §X.Y}.
  \item \textbf{Novel marker}: Novel theorems (those not present in published
        papers) carry a comment \texttt{-- Novel: not in source papers}.
\end{enumerate}

\midrule

\bottomrule

\subsection*{Comment Header Format}

Every Lean file begins with a header block:

\begin{lstlisting}
/-!
# Module Name

Brief description of the module's role in the FRFP formalization.

## Dependencies
- List of imported modules

## Key results
- Theorem 1: brief statement
- Theorem 2: brief statement

## Axiom sources
- Reference 1
- Reference 2
-/
\end{lstlisting}
