This appendix records all 11 proposals generated by the Lean formalization process — cases where Lean's type checker, proof obligations, or Mathlib integration forced precision that revealed gaps, ambiguities, or implicit assumptions in the original FRFP papers.

These proposals represent the primary mechanism by which formal verification acts as a theory development tool, not merely a validation step.

```
FRFP paper (informal)
       ↓
Lean formalization (forces precision)
       ↓
Gaps, ambiguities, new requirements surface
       ↓
New formal structures, corrected definitions, recommendations
       ↓
Proposed back to FRFP paper
```

## C.3 Full Proposal Details

### P-01 — Reduction Acts on Objects, Not Morphisms (Grothendieck Architecture)

**Category**: Architecture clarification  
**Emerged from**: Grothendieck construction formalization  
**Lean location**: `Frfp/Core/Grothendieck.lean`

**What Lean exposed**: The paper was ambiguous about whether reduction steps operate on configurations (Grothendieck objects), morphisms, or syntax terms. Lean's type system forced an explicit architectural decision: reduction is a relation on `GrothendieckObject` (configurations), not on morphisms. A morphism is induced by a reduction step but is distinct from it.

```lean
-- Reduction step is a relation on GrothendieckObject
-- NOT a GrothendieckMorphism
-- But it INDUCES a morphism:
theorem reduction_induces_morphism :
    ReductionStep cfg1 cfg2 →
    ∃ (m : GrothendieckMorphism), m.source = cfg1 ∧ m.target = cfg2
```

**Proposed paper addition**: Explicit statement: "Reduction is a relation on objects (configurations). A morphism is induced by a reduction step, but the reduction step itself is distinct from the morphism."

### P-02 — Run-Trajectory Correspondence: `runToω` Formal Bridge

**Category**: New formal structure (bijection proof)  
**Emerged from**: OperationalSemantics formalization  
**Lean location**: `Frfp/Core/OperationalSemantics.lean`

**What Lean exposed**: Remark A.104 treated runs and stochastic trajectories as corresponding, but did not define the explicit bijection. Lean required a concrete map with injectivity and measurability properties.

```lean
-- Sample space of allowed stochastic trajectories
Ωallowed : Type

-- Inclusion into full sample space
ωallowed_to_ω : Ωallowed → Ω

-- Main correspondence map (NEW — not explicit in paper)
runToω : {ρ // Runs P ρ} → Ωallowed

-- Inverse map (noncomputable)
ωToRun : Ωallowed → {ρ // Runs P ρ}

-- Injectivity (had to be axiomatized)
axiom runToω_injective : runToω ρ1 = runToω ρ2 → ρ1 = ρ2

-- Round-trip property (had to be axiomatized)
axiom runToω_roundtrip : ωToRun (runToω ρ) = ρ
```

**Proposed paper addition**: Remark A.104 should be extended to explicitly define `runToω`, state its injectivity, state the round-trip property, and state measurability as a condition.

### P-04 — Observable Correctness: `Sem`, `gamma`, `obs`, `CorrectnessJudgment`

**Category**: New type / concept made explicit  
**Emerged from**: Tacit dependence formalization  
**Lean location**: `Frfp/Core/TacitDependence.lean`

**What Lean exposed**: Formalizing the tacit-dependent correctness predicate required making implicit concepts explicit:

```lean
axiom Sem : GrothendieckObject → Object          -- Semantic evaluation
axiom gamma : Object → CorrectnessJudgment       -- Observable correctness
noncomputable def obs : Runs(P) → CorrectnessJudgment :=
    gamma ∘ Sem ∘ initial

inductive CorrectnessJudgment
  | correct   -- Tacitly correct (human validates)
  | incorrect -- Tacitly incorrect (e.g., hallucination detected)
  | unknown   -- Cannot determine
```

**Proposed paper addition**: Introduce `CorrectnessJudgment` as a first-class type in A.11.5, explicitly define `Sem` and `gamma`, and state `obs` as their composition.

### P-05 — Lifted Action Commutativity (Confluence Key Lemma)

**Category**: New property required for proof  
**Emerged from**: Confluence proof attempt (Theorem A.7.6)  
**Lean location**: `Frfp/Core/Confluence.lean`

**What Lean exposed**: The paper states Theorem A.7.6 (confluence) but does not make explicit the commutativity property the proof requires:

```lean
-- KEY PROPERTY: Navigation action commutes with explicit reduction
axiom lifted_action_commutes :
    ∀ cfg1 cfg2 nav,
      ExplicitReduction cfg1 cfg2 →
      ExplicitReduction (applyNav nav cfg1) (applyNav nav cfg2)

-- Navigation preserves boundary morphisms
axiom lifted_action_preserves_boundary : ...
```

**Proposed paper addition**: Before Theorem A.7.6, add a lemma: "Lifted action commutativity: navigation commutes with explicit reduction." This makes the confluence proof machinery transparent.

### P-06 — Normal Forms Are Unique Only Modulo Navigation Equivalence

**Category**: Precision correction  
**Emerged from**: SemanticCorrectness formalization  
**Lean location**: `Frfp/Core/SemanticCorrectness.lean`

**What Lean exposed**: The paper claims absolute uniqueness of normal forms. Lean showed uniqueness holds only modulo navigation equivalence — two normal forms from the same configuration are navigation-equivalent, not necessarily identical.

```lean
theorem unique_nf_mod_nav :
    ∀ cfg nf1 nf2,
      CombinedReductionStar cfg nf1 →
      CombinedReductionStar cfg nf2 →
      IsNormalForm nf1 → IsNormalForm nf2 →
      NavEquivalent nf1 nf2   -- ≡ₙ, not =
```

**Proposed paper correction**: Revise the normal-form uniqueness statement to: "Normal forms are unique modulo the navigation equivalence relation `≡ₙ`."

### P-07 — Credence Bounds and Degradation Clamping Must Be Explicit

**Category**: Precision / type-safety  
**Emerged from**: Institutional layer formalization  
**Lean location**: `Frfp/Core/InstitutionalLayer.lean`

**What Lean exposed**: The paper's credence notation does not make explicit the `[0,1]` bound, and the degradation formula does not show clamping.

```lean
structure Credence where
  value : Rat
  nonneg : 0 ≤ value
  le_one : value ≤ 1

-- Paper (implicit): credence' = credence - δ·t
-- Lean (explicit): credence' = max 0 (min 1 (credence - δ·t))
```

**Proposed paper additions**:
1. Declare `Credence ∈ [0,1]` explicitly in A.12.
2. Write degradation formula with clamping: $c'(t) = \max(0, \min(1, c - \delta \cdot t))$.

## C.4 Key Takeaways

**Verification as theory development**: Proposals P-01 through P-08 are new formal content — either absent from the paper or present only informally.

**Implicit assumptions surface**: P-01, P-05, P-06, and P-07 expose implicit assumptions the paper relies on but never states. These are the most valuable verification outputs.

**Axioms to theorems signals mathematical maturity**: P-03 and P-08 show that as Lean/Mathlib matured, previously necessary axioms became provable. The axioms were conservative placeholders, not foundational compromises.

**Structural feedback is unique to formalization**: P-09, P-10, P-11 are structural recommendations that are very hard to generate from informal review. Only by formalizing every definition and tracing dependencies does the natural chapter structure become apparent.
