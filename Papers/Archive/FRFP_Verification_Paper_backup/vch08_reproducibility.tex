\subsection{Build Instructions}
% -------------------------------------------------------------------

\begin{lstlisting}[language=bash]
# 1. Install elan (Lean version manager)
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh

# 2. Install the pinned Lean version
elan install leanprover/lean4:v4.29.0

# 3. Enter the project directory
cd FRFP_Math_Verification/

# 4. Download Mathlib cache (avoid rebuilding Mathlib from source)
lake exe cache get

# 5. Build the full project
lake build

# Expected output:
# [  3305 jobs] Build completed successfully.
\end{lstlisting}

\subsection{Build Validation Checklist}
% -------------------------------------------------------------------

Before tagging a release:

\begin{enumerate}
  \item[$\square$] \texttt{lake build} exits 0 with exactly 3305 jobs.
  \item[$\square$] \texttt{grep -r '\textbackslash bsorry\textbackslash b' | grep -v '\^{}\textbackslash s*--'} returns empty.
  \item[$\square$] All axioms have \texttt{-- Reference:} citation comments.
  \item[$\square$] Executable report (\texttt{lake exe frfpReport}) runs without error.
  \item[$\square$] Minimal modules compile independently (\texttt{lake build Frfp.Minimal}).
  \item[$\square$] Sepsis example produces expected output.
  \item[$\square$] \texttt{lean-toolchain} and \texttt{lake-manifest.json} are committed.
\end{enumerate}

\subsection{Known Limitations}
% -------------------------------------------------------------------

\begin{enumerate}
  \item \textbf{Mathlib dependency}: The formalization depends on Mathlib at a
        specific version. If Mathlib changes breaking APIs, the build may require
        updates.

  \item \textbf{Noncomputable definitions}: Several definitions involving
        classical logic or real arithmetic are marked \texttt{noncomputable}.
        These are logically valid but cannot be executed as programs.

  \item \textbf{Float axioms are assumed}: IEEE 754 properties are axiomatized
        rather than derived from a verified hardware model. This is standard
        practice in proof assistants.

  \item \textbf{Consensus theorem scope}: The consensus no-grounding theorem
        applies within the formal model. Its applicability to real AI systems
        depends on the accuracy of the formalization hypotheses.
\end{enumerate}
